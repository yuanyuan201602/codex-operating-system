# 战役地图视频：从研究到成片

适合用 AI 协助制作地图解说视频的创作者。创作者提供题材、参考和观感判断，AI 协助检索、整理、编写动画与检查；人工史料判断和视觉验收仍然重要。本流程源自斯摩棱斯克项目的实际制作，具体工程与命令见 [案例说明](smolensk-runbook.md)。

整体顺序：读取工程 → 拆解参考 → 整理史料 → 写脚本与时间轴 → 构建地图和画面 → 检查短样 → 输出与检查成片 → 保存可继续修改的工程。出现问题时，回到对应一层修正。

## 1. 先确定当前要做什么

读取已有交接、史料、分镜、源代码、素材、成片和检查记录，再确定最新入口。旧文件上的“完成”不能代表当前版本；先核对文件、尺寸、时长和实际画面。

明确题材与时间范围、目标观众、横竖屏、时长、旁白语言、参考素材和本次交付范围。已有决定直接沿用。保存可恢复的当前版本，给新输出单独命名，避免覆盖用户正在使用的成片。

不要在这里生成一套与项目并行的管理文档。后续结果写回已有史料、分镜和交接；新项目只创建真正需要的记录。

## 2. 把“像参考”拆成可观察的画面

先说明实际拿到的是完整原片、截图片段，还是只有标题和页面文字。完整原片才能支持整体节奏、镜头运动和声音比较。

观察这些内容，并挑最影响观感的差距先改：

| 观察对象 | 要回答的问题 |
|---|---|
| 画幅与取景 | 战役沿哪个方向展开？关键地点占多大面积？ |
| 地图 | 地表纹理、河流与控制区是否能同时看清？ |
| 阵营符号 | 大小、密度、排列是否自然？哪些代表部队？ |
| 数字与文字 | 日期、兵力、地名、字幕的阅读顺序是什么？ |
| 运动 | 若有视频，何时停住、放大、转场，变化是否跟随解说？ |

选择开场、信息最密处、重大转折和结尾的对应画面做比较。借鉴表达方法，地图数据、素材和音轨各自核查来源与使用条件；对标不意味着可直接搬用原片。

## 3. 先把史实变成可画的数据

围绕脚本必须使用的事件查资料。优先采用原始作战图、档案、官方战史和学术研究；百科、研究者网站与科普视频可帮助定位线索，但不能把转引写成亲读原著。

把一个事件记录为：**日期或区间｜地点及坐标｜部队或阵营｜发生的变化｜来源与页码/链接｜核实状态**。对于冲突，保留双方说法并说明采用理由；无法支撑精确日期时，用区间或不突出该日期。关键位置、番号和合围节点无法核实时，不靠 AI 补全。

另外维护两类数据：

- **地理与几何**：城镇、河流、战线关键帧、部队节点、包围圈与通道。统一坐标约定，代码建议明确为 `[经度, 纬度]`，不要直接照搬“纬度在前”的表格。现代地名坐标须核对是否对应历史目标。
- **数字口径**：每项兵力、俘虏和损失记录统计方、范围、时间与含义。没有逐日数据时按阶段展示，不能插值生成似乎精确的每日计数。

战线由关键节点之间的形变生成时，标为示意。开放通道变成封闭包围圈属于形状连接关系变化，应显式定义事件，不能仅让两个多边形慢慢重叠。现代卫星图可做背景，不能证明历史时期的道路、土地利用或战况。

## 4. 让脚本、日期和地图共用一条时间轴

先建立清楚的叙事：在哪里、谁在行动、局面如何改变、结果是什么。为每段口播绑定历史日期、画面事件、镜头目标和必须看见的地名。

建议在现有分镜中增加这些字段，而非再造一份表：

`起止秒/帧 → 历史日期 → 口播 → 战线或部队变化 → 镜头 → 必须出现的地名/数字`

先用临时声音验证长度；已有合适口播就沿用。关键动作以实际音频对齐，例如口播“合拢”时，日期与包围圈状态同步切换。需要停顿解释时明确冻结哪些内容，不能字幕停住而地图继续变化。最终换声音后重新校准，不能只按文字长度估时。

## 5. 地理层稳定，画面层负责可读性

把地图拆成四层，各自承担清晰责任：

| 层 | 内容与约束 |
|---|---|
| 地理层 | 地形、河湖、城市、历史时期适用的道路；保存出处和覆盖范围 |
| 战况层 | 战线、控制区、部队位置、合围状态；由历史节点和时间轴驱动 |
| 镜头层 | 全局、局部取景、平移与缩放；服务当前叙事 |
| 信息层 | 日期、地名、番号、数字、字幕、资料说明；在屏幕上排版 |

拥挤时依次考虑：减少同屏非必要信息、镜头靠近重点、缩短文字、增加引线、错时显示、调整字号。城市点和部队地理坐标保持独立。地理宽度标注应连接实际锚点，不能只是一个浮在角落的数字。

有番号的旗标表示具体部队；无番号小旗如只表现控制区氛围，必须说明不代表数量。阵营图案根据题材和用户约定处理。斯摩棱斯克案例使用不含卐字的原创替代标识，并说明它不是制式军旗；换题材时重新核对，不能当成通用历史旗帜。

先看现有工程是否满足这些要求。斯摩棱斯克沿用 Canvas 2D、Chrome 捕帧和 FFmpeg，没有改成 HyperFrames 或 Remotion。新工程确需技术选型时，再定向阅读最相关的开源实现、许可和关键代码，避免只因热门就引入整套框架。

## 6. 先检查最难的一段

输出几张关键静帧和一段覆盖主要风险的短样，例如开口收窄、合围、突围。15–30 秒通常便于快速判断，但长度以实际问题为准。

静帧检查文字、地名、颜色、旗标、来源说明；连续播放检查跳字、闪烁、转场和运动方向。对照参考判断地表质感、符号密度和数字层级。修改后重看受影响片段，不要在同一结构性问题上无限调参数。

| 症状 | 优先检查与处理 |
|---|---|
| 缩小字号仍放不下 | 重新检查画幅、镜头和信息密度 |
| 标签避让后部队位置变了 | 分离地理坐标与屏幕文字位置 |
| 静帧好看，连续播放闪烁 | 固定排位计划，平滑淡变，抑制短暂出现 |
| 没有重叠，但观众找不到地点 | 增加“口播地点必须可见”的叙事检查 |
| 进度拖动后画面不同 | 排查依赖上一帧的状态，固定随机种子 |
| 技术合格但仍不像参考 | 重新比较取景、地表对比、符号密度与数字比例 |

## 7. 输出后检查实际 MP4

短样解决主要问题后再渲染全片。持续出现的地理和布局约束适合逐帧检查；日期切换、包围圈开合、关键地名和镜头中心需要单独的语义条件。检查条件必须随当前战役与时长修改，不能沿用旧片的帧数直接判通过。

成片检查覆盖四件事：

1. **画面**：从最终编码 MP4 抽帧，回看密集段、地名、数字引线、合围节点和转场；检查完整解码、分辨率、帧率、帧数及字形。
2. **声音**：实际听开头、关键事件和结尾，检查口播与画面同步、削波和意外静音。有音乐时重点听混音后的收尾，不能以“有音轨”替代听感。资料卡静音可以是有意设计。
3. **播放器**：用交付入口真实播放，拖动进度、跳章节、重载或重新打开。通过网页交付大文件时核对范围请求与定位能力。
4. **复现**：抽查任意指定帧与连续渲染一致，检查记录对应同一个最终文件，可用哈希绑定。

发现问题就修复受影响的一层并重做对应检查。渲染完成、几何检查通过、用户认可观感是不同证据，交付时分别说明。

## 8. 保存下一次还能接着做的成果

交付当前成片、可用预览、源文件与素材出处、分镜时间轴、检查结果和上一版恢复入口。在已有交接中记录当前版本、执行命令、环境依赖、已知限制及用户已确认的决定。

保留素材、配音和参考各自的使用条件。本案例原配音的公开商用授权未核实；若以后要求公开发布，应先核对或替换。制作完成本身不包含发布授权。

换题材时，可沿用分层设计、标签策略、渲染和检查方法；必须重新整理史料、地理范围、战线与部队节点、合围事件、脚本、镜头及检查条件。交付的是可复用方法，不能宣称只替换战役名称就能自动得到可靠成片。
