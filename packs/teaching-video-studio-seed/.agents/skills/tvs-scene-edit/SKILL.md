# 受控的局部修改

模型不保证“只改这一处”，所以靠流程保证：隔离副本、路径白名单、关键帧回归、通过才合并。

## 1. 先分类，再动手

| 类型 | 例子 | 允许改动 |
|---|---|---|
| `scene` 镜头内 | 换例子、改措辞、改配色布局、加高亮 | 仅 `lessons/<id>/scenes/<目标镜头>/` |
| `duration` 时长 | “这段慢一点”“压缩到 10 秒” | 仅 `manifest.json` 里目标镜头的 `durationSec` |
| `global` 全局 | 换风格、换字体、改所有字幕 | 必须先让用户确认影响范围，再加 `--confirm-global` |

- 用户没指明镜头：先问是哪个镜头；涉及全片的要求按 `global` 处理并确认。
- 先把计划用一句话告诉用户：“这次会改：<镜头>，类型：<类型>，连带影响：<如后面镜头整体顺延>”。改时长时让用户选保留总时长还是延长视频（保留总时长要同时改另一个镜头的时长，那就是两个目标镜头）。
- 字幕文字属于镜头内修改，改 `scene.json`；字幕必须仍满足阅读速度检查。

## 2. 在隔离副本里改

```bash
npm run tvs -- edit begin <lessonId> --kind scene --scenes s02-branch --request "<用户原话>"
# 输出候选版本目录，只在该目录里修改
npm run tvs -- edit verify <目录>
npm run tvs -- edit accept <目录>     # 或 edit discard <目录>
```

要求：主工作区必须干净；基准版本过期时请求会被拒绝，需重新发起。

## 3. verify 失败怎么办

- **越界修改**：撤销越界文件。确实需要的话回到第 1 步，扩大范围并得到用户确认，不要硬塞。
- **禁用写法 / 类型错误**：在目标镜头内修好。
- **目标镜头关键帧没变化**：修改没生效，重做。
- **未选镜头画面变了**：说明有隐藏依赖，如实报告，不要绕过检查。
- 不得修改 `scripts/`、`src/kit/` 来让检查通过。

## 4. 合并后

告诉用户：新版本号、改了哪些文件、和旧版相比的变化、有无连带影响。旧版本在 git 历史里，随时可回退（`git revert <版本>`）。取消或失败时旧预览不受影响。
